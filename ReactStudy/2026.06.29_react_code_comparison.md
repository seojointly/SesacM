# React CDN 환경에서의 코드 구조 비교 분석 보고서

본 문서는 React 입문 과정에서 CDN(Content Delivery Network)과 Babel standalone을 활용해 개발 환경을 구축할 때 자주 접하는 두 가지 코드 패턴의 차이점, 장단점 및 강사님이 코드를 업데이트한 의도를 체계적으로 정리한 가이드입니다.

---

## 1. 코드 구조 비교

### 1번 코드 (직관적이고 단순한 구조)
```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <script crossorigin src="https://unpkg.com/react@18/umd/react.development.js"></script>
  <script crossorigin src="https://unpkg.com/react-dom@18/umd/react-dom.development.js"></script>
  <script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>
  <title>Document</title>
</head>
<body>
  
<div id="root"></div>
<script type="text/babel" data-presets="typescript,react">
  // 리액트 코드가 바로 작성되는 공간
</script>

</body>
</html>
```

### 2번 코드 (명시적이고 우회적인 구조)
```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <script crossorigin src="https://unpkg.com/react@18/umd/react.development.js"></script>
  <script crossorigin src="https://unpkg.com/react-dom@18/umd/react-dom.development.js"></script>
  <script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>
  <title>Document</title>
</head>
<body>
  
<script type="text/babel" data-presets="typescript,react">
  /** @type {any} */
  const globalWindow = window;
  const { React, ReactDOM } = globalWindow;
</script>

<div id="root"></div>
<script type="text/babel" data-presets="typescript,react">
  // 분리된 스크립트 공간
</script>

</body>
</html>
```

## 2. 두 코드의 핵심 차이점

| 비교 항목 | 1번 코드 | 2번 코드 |
| :--- | :--- | :--- |
| **구조의 간결성** | 매우 직관적이고 군더더기가 없음 | 스크립트가 분리되어 있고 우회 코드가 존재함 |
| **전역 객체 접근** | `window`에 자동 등록된 `React` 객체를 직접 호출 | `window`를 별도 변수에 대입 후 구조 분해 할당으로 추출 |
| **IDE(편집기) 힌트** | 설정에 따라 경고(빨간 줄)가 발생할 수 있음 | `JSDoc` 문법(`/** @type {any} */`)으로 경고를 강제 억제 |
| **DOM 선언 순서** | `div#root`가 스크립트보다 먼저 선언되어 안전함 | 첫 스크립트가 DOM보다 먼저 실행됨 (초기화 목적) |

## 3. 일반적인 프론트엔드 관점: 왜 1번이 더 좋은가?

웹 표준과 리액트의 동작 원리만 두고 본다면 **1번 코드가 훨씬 좋은 코드**입니다.

1. **불필요한 전역 객체 재할당 방지**
   - CDN 스크립트가 로드되면 브라우저의 최상위 객체인 `window`에 `React`와 `ReactDOM`이 자동으로 바인딩됩니다. 따라서 굳이 `const { React } = window;`와 같이 변수를 새로 선언하여 메모리를 쓸 필요가 없습니다.
2. **코드 파편화 방지**
   - 2번 코드는 `<script>` 태그가 두 개로 쪼개져 있습니다. HTML 파일 안에서 스크립트 영역이 무분별하게 나누어지면 전체적인 가독성이 떨어지고 관리가 복잡해집니다.
3. **자연스러운 데이터 흐름**
   - 1번 코드는 React가 화면을 그릴 대상인 `<div id="root">`를 먼저 배치한 뒤 스크립트를 실행하므로 DOM 렌더링 순서상 안전합니다.

## 4. 강사님이 2번 코드로 업데이트한 진짜 이유 (교육적 목적)

그렇다면 강사님은 왜 더 복잡해 보이는 2번 코드로 수정을 제안하셨을까요? 여기에는 학습을 돕기 위한 중요한 의도가 숨어 있습니다.

### ① 동작 원리의 시각화 (동작 출처 명시)
1번처럼 쓰면 `React`라는 객체가 자바스크립트 내장 기능인지, Babel이 만든 것인지 입문자 단계에서는 혼란스러울 수 있습니다. 강사님은 **"우리가 HTML 상단에서 불러온 CDN 라이브러리가 사실 브라우저의 전역 객체(`window`)에 들어있고, 그것을 꺼내 쓰는 것이다"**라는 원리를 명확히 시각화하여 보여주고자 하신 것입니다.

### ② 개발 툴(VS Code) 에러 및 경고 해결
HTML 파일 내부에서 `type="text/babel"` 스크립트를 작성하면, VS Code가 이를 완벽한 자바스크립트/타입스크립트 환경으로 인식하지 못해 `React`라는 단어에 빨간 밑줄(에러 경고)을 긋거나 자동 완성 기능을 지원하지 않는 경우가 많습니다.
- 이때 `/** @type {any} */ const globalWindow = window;` 코드를 넣어주면, VS Code에게 **"이 변수는 어떤 타입도 될 수 있으니 검사를 건너뛰어라"**라고 지시하게 됩니다. 
- 이를 통해 강사님 화면이나 수강생 화면에서 지저분한 경고 표시가 뜨는 것을 방지하고, 원활한 실습 환경을 만들기 위함입니다.

### ③ 모듈 시스템(`import`) 전단계를 위한 징검다리
리액트 실습이 고도화되거나 실제 현업 프로젝로 넘어가면 CDN 방식을 버리고 `npm` 시스템 기반에서 아래와 같이 코드를 작성하게 됩니다.
```javascript
import React, { useState } from 'react';
import ReactDOM from 'react-dom';
```
2번 코드의 `const { React, ReactDOM } = globalWindow;` 구조는 향후 배우게 될 이 **정식 import 문법과 시각적으로 매우 유사**합니다. 나중에 맞이할 구조에 미리 익숙해지도록 의도적으로 구조 분해 할당(Destructuring) 문법을 노출한 것입니다.

## 5. 결론 및 권장 학습 방향

- **강의 진행 중에는:** **강사님의 2번 코드를 그대로 복사해서 따라 하시는 것이 좋습니다.** 향후 진행되는 강의 코드들이 `globalWindow`나 미리 할당된 변수를 기준으로 작성될 가능성이 높기 때문에 흐름을 맞추는 것이 안전합니다.
- **머릿속으로는:** *"아, 2번 코드는 실습 환경에서 **편집기 에러를 막고 원리를 명시적으로 보여주기 위한 교육용 코드**구나! 실제 나중에 제대로 된 리액트 앱을 만들 때는 1번처럼 직관적으로 쓰거나 정식 `import` 문법을 쓰게 되겠구나"* 하고 완벽히 이해하고 넘어가시면 됩니다.
