# React 배열 렌더링 및 Props 전달 오류 디버깅 가이드

본 문서에서는 React에서 배열 데이터를 활용해 컴포넌트를 반복 렌더링할 때 흔히 발생하는 오류 예시와 올바른 해결 방법을 정리합니다. 특히 **데이터 흐름(Props 전달)**, **변수 스코프(접근 범위)**, 그리고 **`map()` 메서드와 `key` 속성의 올바른 사용법**에 대해 다룹니다.

---

## 1. 기본 배열 렌더링 시 발생한 오류 (Case 1)

### 문제의 코드
```html
<div id="root1"></div>
<div id="root2"></div>
<script type="text/babel">
  {
    const ListComp = ( { items } ) => {
      return (
        <ul>
          {items.map((item, i) => (<li key={i}>{item}</li>))}
        </ul>
      );
    }

    const names = ["tom", "jessica", "alice"];
    // 오류 발생 지점
    ReactDOM.createRoot(document.getElementById('root3')).render(<ListComp items={names}/>);
  }
</script>
```

### 오류 원인
* **존재하지 않는 HTML 엘리먼트 참조:** 자바스크립트 코드에서는 `document.getElementById('root3')`를 호출하여 React 루트를 생성하려고 시도했으나, HTML 바디 구조에는 `root1`과 `root2` 엘리먼트만 존재하고 `root3`는 정의되어 있지 않습니다. 이로 인해 `null`에서 속성을 읽을 수 없다는 런타임 에러가 발생합니다.

### 해결 방법 (택일)
1. **HTML 구조 수정:** HTML 바디 영역에 `<div id="root3"></div>` 엘리먼트를 추가합니다.
2. **자바스크립트 코드 수정:** 기존에 존재하는 엘리먼트를 가리키도록 `document.getElementById('root1')` 등으로 변경합니다.

> 💡 **Tip (Key 선택 기준):** 단순 정적 데이터 표시는 배열의 인덱스(`i`)를 `key`로 써도 무방하지만, 데이터의 정렬, 추가, 삭제가 일어나는 동적 배열의 경우 데이터 자체의 고유 ID 값을 `key`로 사용하는 것이 React의 성능 최적화와 올바른 컴포넌트 상태 유지에 필수적입니다.

## 2. 하위 컴포넌트 분할 및 Props 오류 (Case 2)

### 문제의 코드
```javascript
// ====== 2. 하위 컴포넌트 분할 배열 렌더링 ======== // 
{
  const ListItemComp = () => {
    return <li key={id}>{list}</li>
  }
  const ListComp = ({ item }) => {
    return(
      <ul>
        {
          list.map( item => <ListItemComp/> )
        }
      </ul>
    );
  }
  const list = [
    {id: 1, name: 'tom'},
    {id: 2, name: 'jessica'},
    {id: 3, name: 'alice'},
  ]
  ReactDOM.createRoot(document.getElementById('root2')).render(<ListComp items={list}/>);
}
```

### 오류 원인 및 개념 설명
1. **정의되지 않은 변수 접근 및 Props 누락 (`ListItemComp`):**
   * 자식 컴포넌트인 `ListItemComp` 내부에서 `id`와 `list`라는 변수를 사용하고 있으나, 인자(Props)로 받은 적도 없고 내부에 선언된 적도 없습니다. (`id is not defined` 에러 발생)
   * 자식 컴포넌트가 부모로부터 데이터를 받아와 독립적으로 작동하려면 **Props(속성)** 통로를 열어주어야 합니다.
2. **`key` 속성의 잘못된 위치:**
   * React에서 `map`을 통해 반복 생성하는 대상은 `<ListItemComp />` 자체입니다. 따라서 `key` 속성은 하위 컴포넌트 내부의 `<li>`가 아닌, **`map` 바로 직속인 상위 컴포넌트 태그**에 위치해야 합니다.
3. **부모 컴포넌트의 인자 불일치:**
   * 외부에서 `<ListComp items={list}/>` 형태로 `items` 속성을 넘겼음에도, 부모 컴포넌트는 매개변수에서 구조 분해 할당으로 `{ item }`을 찾고 있습니다. 이름이 일치하지 않아 데이터 접근이 불가능합니다.
4. **`map()` 메서드의 메커니즘 오해:**
   * `list.map(item => ...)` 내부에서 반복자로 지정한 변수 이름과 자식에게 전달하는 변수명이 어긋나 데이터가 정상적으로 하위로 흐르지 못했습니다.

## 3. `item` 변수와 `name` 인자의 개념 이해

### (1) `item` 변수란?
자바스크립트의 `map()` 배열 메서드는 배열 내부의 요소를 순서대로 하나씩 꺼내어 지정한 콜백 함수를 실행합니다. 이때 **"지금 순서에서 처리하고 있는 바로 그 데이터 조각"**을 담아두는 바구니 역할을 하는 임시 변수가 `item`입니다. (이름은 자유롭게 변경 가능)

예를 들어 배열이 `[{id:1, name:'tom'}, {id:2, name:'jessica'}]` 일 때, `map(item => ...)`은 다음과 같이 작동합니다.
* **1회차 실행:** `item` 변수에 `{id:1, name:'tom'}` 대입 후 본문 실행
* **2회차 실행:** `item` 변수에 `{id:2, name:'jessica'}` 대입 후 본문 실행

### (2) `name` 인자(Props)란?
자식 컴포넌트인 `ListItemComp`는 독립된 함수형 블록이므로, 외부에서 알려주지 않으면 자신이 'tom'을 그려야 하는지 'jessica'를 그려야 하는지 모릅니다. 부모가 가진 데이터를 자식 컴포넌트 내부로 안전하게 전달하기 위한 파라미터 게이트웨이가 바로 **Props**입니다.

## 4. 실무형 객체 데이터 구조 및 JSDoc 디버깅 (Case 3)

타입 힌트 명시를 위해 JSDoc 규칙과 객체 통째 전달 방식을 도입할 때 발생한 실수를 교정한 사례입니다.

### 문제의 코드
```javascript
// ====== 2. 하위 컴포넌트 분할 배열 렌더링 ======== // 
{
  /** 
   * @typeof {Object} UserItem
   * @property {number} id
   * @property {String} data 
   */
  
  /** @type {React.FC<{data: UserItem}>} */
  const ListItemComp = ({ data }) => {
    return <li key={id}>{data.name}</li>
  }

  /** @type {React.FC<{items: UserItem[]}>} */
  const ListComp = ({ item }) => {
    return(
      <ul>
        {
          list.map( lsit => <ListItemComp key={item.id} data={item} /> )
        }
      </ul>
    );
  }

  /** @type {UserItem[]} */
  const list = [
    {id: 1, name: 'tom'},
    {id: 2, name: 'jessica'},
    {id: 3, name: 'alice'},
  ]
  ReactDOM.createRoot(document.getElementById('root2')).render(<ListComp items={list}/>);
}
```

### 수정해야 할 포인트
* **JSDoc 문법 오류:** 사용자 정의 타입을 지정할 때는 `@typeof`가 아니라 **`@typedef`**가 올바른 표준 문법입니다. 또한 객체 속성은 `data`가 아니라 실제 key값인 `name`으로 기재해야 올바르게 인지됩니다.
* **중첩 스코프 에러 및 반복문 오타:** `list.map( lsit => ... )` 구조에서 매개변수를 `lsit`라는 오타로 선언해놓고, 정작 우측 컴포넌트 속성에서는 정의되지 않은 상위의 `item` 변수(`item.id`, `item`)를 참조하여 정상 동작하지 않았습니다. Component 재사용성을 위해 전역 변수인 `list` 대신 Props로 전달받은 배열을 가리키는 것이 좋습니다.

## 5. 최종 디버깅 완료본 코드

모든 문법 오류와 렌더링 규칙을 올바르게 수정한 정석적인 구현 코드는 아래와 같습니다.

```javascript
// ====== 2. 하위 컴포넌트 분할 배열 렌더링 (최종 완성본) ======== // 
{
  // 1. 객체 데이터 타입 명확히 정의
  /** 
   * @typedef {Object} UserItem
   * @property {number} id
   * @property {string} name 
   */
  
  // 2. 자식 컴포넌트: data 객체를 받아 내부 속성 활용 (내부 key 제거)
  /** @type {React.FC<{data: UserItem}>} */
  const ListItemComp = ({ data }) => {
    return <li>{data.name}</li>;
  }

  // 3. 부모 컴포넌트: 외부에서 넘겨준 items 속성을 구조 분해 할당으로 온전히 수신
  /** @type {React.FC<{items: UserItem[]}>} */
  const ListComp = ({ items }) => {
    return (
      <ul>
        {
          // 4. items 배열을 순회하며 개별 원소를 singleItem에 매핑
          // 5. key 속성은 map 직속 자식인 최상위 컴포넌트 태그에 부여 (실무 표준 방식)
          items.map(singleItem => (
            <ListItemComp 
              key={singleItem.id} 
              data={singleItem} 
            />
          ))
        }
      </ul>
    );
  }

  // 6. 데이터 배열 선언
  /** @type {UserItem[]} */
  const list = [
    {id: 1, name: 'tom'},
    {id: 2, name: 'jessica'},
    {id: 3, name: 'alice'},
  ];
  
  // 7. HTML 내 존재하는 유효한 root2 엘리먼트에 안전하게 마운트 및 렌더링
  ReactDOM.createRoot(document.getElementById('root2')).render(<ListComp items={list}/>);
}
```

### 💡 핵심 요약
1. **보내는 이름과 받는 이름 매칭:** 부모가 `<Comp items={...} />`로 보냈다면 자식 매개변수는 반드시 `({ items })`로 받아야 합니다.
2. **`map` 내부 식별자 일치:** `arr.map(x => ...)`을 썼다면 루프 내부에서 데이터 조각을 다룰 때 반드시 설정한 변수 이름 `x`를 사용해야 스코프 오류가 나지 않습니다.
3. **`key` 위치 원칙:** 고유 key값은 언제나 `map()` 함수 바로 직속 하위 컴포넌트 요소에 바인딩합니다.
