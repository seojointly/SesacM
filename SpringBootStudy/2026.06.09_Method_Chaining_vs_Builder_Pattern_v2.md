# 메서드 체이닝(Method Chaining)과 빌더 패턴(Builder Pattern)의 차이점

메서드 체이닝과 빌더 패턴은 모두 코드를 가독성 있게 만들고 객체 설정을 깔끔하게 도와주는 기법이지만, 둘은 구체적인 목적과 구현 방식에서 명확한 차이가 있습니다. 

쉽게 요약하자면 **메서드 체이닝은 구현 기법(문법)**이고, **빌더 패턴은 디자인 패턴(구조)**입니다.

---

## 1. 메서드 체이닝 (Method Chaining)
메서드 체이닝은 여러 메서드를 이어서 한 줄로 호출하는 **코딩 스타일이자 기법**입니다. 각 메서드가 객체 자체(`this`)를 반환하도록 설계하여, 마침표(`.`)를 연속으로 사용할 수 있게 만듭니다.

* **목적:** 코드의 간결성과 가독성 향상
* **특징:** 대상 객체 자체가 계속 수정되면서 전달됩니다. 별도의 생성 클래스가 필요 없습니다.

```java
// 메서드 체이닝 예시 (StringBuilder)
StringBuilder sb = new StringBuilder();
sb.append("Hello ").append("World!").append(" 2026");
```

---

## 2. 빌더 패턴 (Builder Pattern)
빌더 패턴은 복잡한 객체의 **생성 과정과 표현 방법을 분리**하는 **디자인 패턴**입니다. 생성자에 인자가 너무 많거나, 객체를 생성할 때 필수 값과 선택 값이 뒤섞여 있을 때 발생하는 문제를 해결하기 위해 사용합니다.

* **목적:** 복잡한 객체의 안전하고 유연한 생성
* **특징:** 보통 데이터 객체(Product) 내부에 별도의 `Builder` 클래스를 둡니다. 값을 채울 때는 메서드 체이닝 기법을 활용하며, 최종적으로 `.build()` 메서드를 호출해야만 원하는 실제 객체가 완성됩니다.

```java
// 빌더 패턴 예시
User user = new User.Builder()
    .name("홍길동")       // 필수값
    .age(30)            // 선택값
    .hobby("Programming") // 선택값
    .build();           // 최종 객체 생성
```

---

## 3. 핵심 차이점 비교

| 구분 | 메서드 체이닝 | 빌더 패턴 |
| :--- | :--- | :--- |
| **개념적 분류** | 코딩 기법 / 스타일 | 소프트웨어 디자인 패턴 |
| **주된 목적** | 가독성 증가, 코드 줄이기 | 객체 생성의 복잡성 해결, 불변 객체 생성 |
| **최종 반환** | 보통 자기 자신(`this`) | 최종적으로 변환된 목적 객체 (`.build()`) |
| **객체의 상태** | 메서드를 호출할 때마다 객체 상태가 계속 변함 | `build()`를 호출하기 전까지는 실제 객체가 생성되지 않음 |
| **불변성 (Immutability)** | 유지하기 어려움 (계속 자기 자신을 수정하므로) | **유지하기 매우 쉬움** (생성 후 수정 불가한 객체 생성 가능) |

### 비유로 이해하기 🧱
* **메서드 체이닝:** 이미 완성된 로봇에 "왼팔 붙여", "오른팔 붙여", "다리 붙여"라고 직접 명령하며 로봇을 계속 조작하는 것과 같습니다.
* **빌더 패턴:** 설계도(Builder)에 "왼팔은 이걸로", "오른팔은 이걸로"라고 요구사항을 다 적은 뒤, 마지막에 "조립 해줘!(`build()`)"를 눌러 완벽하고 수정 불가능한 로봇을 한 번에 찍어내는 것과 같습니다.

**결론적으로, 빌더 패턴은 객체를 안전하게 생성하기 위해 '메서드 체이닝'이라는 문법적 기법을 도구로써 활용하는 관계입니다.**
