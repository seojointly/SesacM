# JPA + Hibernate 테스트 실행 로그 분석 (VS Code 기준)

---

# 1. Product 테스트 (IDENTITY 전략)

## 1-1. 엔티티 코드

```java
@Entity
@Table(name = "products")
public class Product {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "product_code", length = 20, unique = true)
    private String productCode;

    @Column(name = "product_name", length = 100, nullable = false)
    private String productName;

    private Integer price;

    private String description;

    private LocalDateTime registeredAt;
}
```

---

## 1-2. 테스트 코드

```java
@Test
void productTest() {

    Product product = new Product();
    product.setProductCode("P001");
    product.setProductName("노트북");
    product.setPrice(1500000);
    product.setDescription("가벼운 노트북");

    entityManager.persist(product);

    System.out.println("Product ID: " + product.getId());
}
```

---

## 1-3. 실제 디버그 콘솔 로그

```
Hibernate:
    create table products (
        id bigint not null auto_increment,
        description longtext,
        product_name varchar(100) not null,
        price integer not null,
        product_code varchar(20) not null,
        registered_at datetime(6),
        primary key (id)
    ) engine=InnoDB

Hibernate:
    alter table products
       add constraint UC_PRODUCT_CODE unique (product_code)

Hibernate:
    insert
    into
        products
        (description, product_name, price, product_code, registered_at)
    values
        (?, ?, ?, ?, ?)

Product ID: 1
```

---

## 1-4. 실행 흐름

persist()
  ↓
INSERT SQL 즉시 실행 (IDENTITY 특성)
  ↓
DB AUTO_INCREMENT 생성
  ↓
Entity에 ID 주입
  ↓
getId() = 1

# 2. User 테스트 (TABLE 전략)

## 2-1. 엔티티 코드

```java
@Entity
@Table(name = "users")
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.TABLE, generator = "user_gen")
    @TableGenerator(
        name = "user_gen",
        table = "user_id_seq",
        pkColumnValue = "User",
        allocationSize = 1
    )
    private Long id;

    @Column(nullable = false, length = 100)
    private String username;

    @Column(nullable = false, length = 100)
    private String email;

    @Enumerated(EnumType.STRING)
    private Role role;

    private LocalDateTime createdAt;
}
```

---

## 2-2. 테스트 코드

```java
@Test
void userTest() {

    User user = new User();
    user.setUsername("홍길동");
    user.setEmail("hong-gildong");
    user.setRole(Role.ADMIN);

    entityManager.persist(user);

    System.out.println("======== User ========");
    System.out.println(user);
}
```

---

## 2-3. 실제 디버그 콘솔 로그

```
Hibernate:
    create table user_id_seq (
        entity varchar(255) not null,
        nextval bigint,
        primary key (entity)
    ) engine=InnoDB

Hibernate:
    insert into user_id_seq(entity, nextval)
    values ('User',0)

Hibernate:
    select
        tbl.nextval
    from
        user_id_seq tbl
    where
        tbl.entity=? for update

Hibernate:
    update
        user_id_seq
    set
        nextval=?
    where
        nextval=?
        and entity=?

======== User ========
User [id=1, username=홍길동, email=hong-gildong, createdAt=null, role=ADMIN]
```

---

## 2-4. 실행 흐름

persist()
  ↓
PK 조회 (select nextval)
  ↓
PK 증가 (update user_id_seq)
  ↓
Entity에 ID 세팅
  ↓
(INSERT는 flush 시점까지 지연 가능)

# 3. Product vs User 비교

| 항목 | Product (IDENTITY) | User (TABLE) |
|------|------------------|--------------|
| PK 생성 위치 | DB | Hibernate |
| 추가 테이블 | 없음 | user_id_seq |
| SQL 흐름 | INSERT 즉시 | SELECT → UPDATE |
| flush | 즉시 | 지연 |
| 성능 | 좋음 | 낮음 |

---

# 4. flush vs commit

persist()
  ↓
영속성 컨텍스트 저장
  ↓
flush()
  ↓
SQL 실행
  ↓
commit()

# 7. 핵심 결론

- Product: DB가 PK 생성 → INSERT 즉시 실행
- User: Hibernate가 PK 관리 → SELECT/UPDATE 발생
- flush 시점이 SQL 실행 타이밍 결정
- commit은 최종 확정 단계
