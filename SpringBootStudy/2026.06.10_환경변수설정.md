# 🛠️ Spring Boot & VS Code 데이터베이스 보안 설정 가이드
> **GitHub 소스코드 유출 방지를 위한 환경 변수 분리 및 `.gitignore` 설정 매뉴얼**

본 문서는 스프링 부트(Spring Boot) 프로젝트에서 MyBatis와 MySQL을 연동할 때, 데이터베이스 접속 정보(`username`, `password`) 같은 민감한 정보가 GitHub 공개 저장소에 하드코딩되어 유출되는 것을 방지하기 위해 작성되었습니다. VS Code 환경에서 환경 변수를 분리하고 Git 추적에서 안전하게 제외하는 전체 과정을 처음부터 끝까지 상세히 설명합니다.

---

## 📂 [준비 단계] 현재 내 프로젝트 구조 확인
시작하기 전, VS Code 좌측 파일 탐색기에서 내 프로젝트가 아래 구조와 일치하는지 확인합니다. 본 가이드는 `EX07_MYBATIS` 프로젝트 구조를 기준으로 작성되었습니다.

```text
EX07_MYBATIS/
├── .gradle/
├── .vscode/                 <-- 2단계에서 설정할 폴더
│   └── launch.json          <-- 2단계에서 수정할 파일
├── src/
│   └── main/
│       ├── java/com/example/mybatis/Ex07MybatisApplication.java
│       └── resources/
│           └── application.yml  <-- 1단계에서 수정할 파일
├── .gitignore               <-- 3단계에서 수정할 파일
└── build.gradle
🧩 1단계: application.yml 수정 (환경 변수 매핑)
기존 application.properties를 yml 파일로 변경한 후, 실제 데이터베이스 계정 아이디와 비밀번호를 파일에 직접 하드코딩하지 않고 스프링 부트가 실행될 때 시스템 환경 변수에서 값을 동적으로 가져오도록 구조를 변경합니다. 이렇게 설정하면 이 파일이 GitHub에 올라가더라도 실제 비밀번호는 노출되지 않아 안전합니다.

src/main/resources/ 경로에 있는 application.yml 파일을 엽니다.

기존 설정을 지우고 아래 내용을 프로젝트 상황에 맞게 복사하여 붙여넣습니다.

YAML
spring:
  datasource:
    # MySQL 드라이버 설정
    driver-class-name: com.mysql.cj.jdbc.Driver
    # 데이터베이스 연결 URL (YOUR_DB_NAME 부분에 실제 MySQL 스키마 이름을 적으세요)
    url: jdbc:mysql://localhost:3306/YOUR_DB_NAME?serverTimezone=Asia/Seoul&useSSL=false&allowPublicKeyRetrieval=true
    
    # 🔥 핵심: 실제 값 대신 시스템 환경 변수를 참조하도록 설정
    username: ${DB_USERNAME}  
    password: ${DB_PASSWORD}  

mybatis:
  # MyBatis 매퍼 XML 파일 위치 설정
  mapper-locations: classpath:mappers/**/*.xml
  # 자바 모델 클래스의 패키지 경로 (본인의 패키지명에 맞게 수정)
  type-aliases-package: com.example.mybatis
💡 ${DB_USERNAME} 문법의 의미
스프링 부트가 구동되는 시점에 호스트 OS 환경이나 개발 툴(VS Code)이 주입해 주는 DB_USERNAME 및 DB_PASSWORD라는 이름의 환경 변수 값을 읽어서 동적으로 맵핑하겠다는 의미입니다.

⚙️ 2단계: VS Code 설정 파일(launch.json)에 환경 변수 주입
스프링 부트가 위에서 명시한 ${DB_USERNAME}과 ${DB_PASSWORD} 자리에 내 로컬 컴퓨터의 실제 MySQL 정보를 주입할 수 있도록 VS Code 디버그 실행 파일(launch.json)을 세팅합니다.

💡 파일 접근 및 설정 방법
프로젝트 최상위 디렉토리에 있는 .vscode 폴더를 클릭하여 펼칩니다.

폴더 내부에 launch.json 파일이 있다면 클릭해서 열고, 만약 없다면 .vscode 폴더를 마우스 우클릭한 뒤 [새 파일]을 선택하여 launch.json 파일을 직접 생성합니다.

파일이 열리면 기존에 VS Code가 자동으로 생성해 둔 설정 키값들이 보일 것입니다. 원래 있던 키값들은 스프링 부트를 실행하는 데 필수적인 정보이므로 절대 지우지 마세요.

기존 설정 중 가장 마지막 항목인 "envFile": "" 우측 끝에 쉼표(,)를 입력하여 문법 오류를 방지한 뒤, 다음 줄에 "env" 블록을 추가합니다.

📝 launch.json 최종 적용 예시
JSON
{
    "version": "0.2.0",
    "configurations": [
        {
            "type": "java",
            "name": "Ex07MybatisApplication",
            "request": "launch",
            "cwd": "${workspaceFolder}",
            "mainClass": "com.example.mybatis.Ex07MybatisApplication",
            "projectName": "EX07_MYBATIS",
            "args": "",
            "envFile": "", // 👈 중요: 기존 마지막 항목 뒤에 반드시 쉼표(,)를 찍어야 합니다!
            
            // ⚠️ 여기에 로컬 환경 변수 블록을 추가하여 실제 비밀번호를 주입합니다.
            "env": {
                "DB_USERNAME": "root",              // 본인의 실제 MySQL 계정 아이디를 입력하세요.
                "DB_PASSWORD": "your_password_123"  // 본인의 실제 MySQL 계정 비밀번호를 입력하세요.
            }
        }
    ]
}
⚠️ JSON 문법 에러 방지 체크리스트

"envFile": "" 뒤에 쉼표(,)를 누락하면 프로젝트 실행 시 JSON 파싱 에러가 발생합니다.

"env" 블록 내부에서 "DB_USERNAME" 줄 끝에는 쉼표(,)가 들어가야 하지만, 마지막 줄인 "DB_PASSWORD" 뒤에는 쉼표가 들어가지 않아야 합니다.

🛡️ 3단계: .gitignore 파일 설정을 통한 GitHub 유출 원천 차단
실제 데이터베이스 비밀번호를 적어둔 .vscode/launch.json 파일이 GitHub 저장소에 업로드되는 대참사를 막기 위해 Git 추적 대상에서 제외해야 합니다.

💡 설정 방법
프로젝트 루트(최상위) 디렉토리에 위치한 .gitignore 파일을 더블클릭하여 엽니다.

파일의 맨 아랫줄로 이동하여 엔터를 치고, 다음 코드를 추가한 뒤 파일을 저장합니다.

Plaintext
# =========================================================================
# VS Code 로컬 디버그 및 환경 변수 설정 파일 제외 (보안 필수)
# =========================================================================
.vscode/launch.json
💡 [선택 사항] .vscode 폴더 전체를 제외하고 싶다면?
협업 과정에서 팀원들 각자의 VS Code 개인 플러그인 설정이나 작업 환경 설정을 공유하지 않고 완전히 독립적으로 관리하고 싶다면, 아래와 같이 작성합니다.

Plaintext
.vscode/
🚀 4단계: 최종 점검 및 애플리케이션 실행
환경 변수가 정상적으로 바인딩되어 데이터베이스가 정상 구동되는지 검증합니다.

VS Code 좌측 가장자리에 있는 사이드바 메뉴에서 [실행 및 디버그] 탭(삼각형 재생 버튼과 벌레 모양 아이콘)을 클릭합니다.

상단 제어창 드롭다운 구성 메뉴에서 실행할 메인 클래스 이름(Ex07MybatisApplication)이 정상적으로 선택되어 있는지 확인합니다.

드롭다운 옆에 있는 녹색 삼각형 [재생(실행)] 버튼을 누르거나 키보드 단축키 F5를 눌러 스프링 부트를 구동합니다.

하단 터미널 콘솔 창에 오류 없이 Tomcat 서버가 정상 가동되면 성공입니다.

🚨 [초비상 외전] 만약 이미 GitHub에 비밀번호를 push해 버렸다면?
.gitignore 설정을 하기 전에 이미 실수로 launch.json 파일을 GitHub 원격 저장소에 올려버린 적이 있다면, 뒤늦게 .gitignore 파일에 등록하더라도 Git이 해당 파일을 계속 추적합니다. 이 경우 터미널을 통해 Git의 캐시(메모리)를 강제로 비워 원격 저장소에서만 제거해야 합니다.

💡 해결 명령어 (순서대로 입력)
VS Code 하단 터미널(Ctrl + ~)을 열고 아래 명령어를 한 줄씩 차례대로 입력합니다.

Bash
# 1. 로컬에 있는 원본 파일은 건드리지 않고, Git 추적 리스트(캐시)에서만 launch.json을 제거합니다.
git rm --cached .vscode/launch.json

# 2. 제외 처리 내역을 로컬 저장소에 기록(커밋)합니다.
git commit -m "Chg: 보안 위반 설정 파일 .gitignore 반영 및 Git 추적 제거"

# 3. 변경 사항을 GitHub 원격 저장소에 push하여 최종 반영합니다.
git push origin main
