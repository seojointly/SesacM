# HttpSecurity.build()와 SecurityFilterChain 이해하기

## 결론

```java
return http.build();
```

는

```text
지금까지 HttpSecurity에 설정한 내용을 기반으로

실제로 동작하는 SecurityFilterChain을 생성한다.
```

라고 이해하면 된다.

---

# 1. HttpSecurity란?

`HttpSecurity`는 Spring Security 설정을 모아두는 빌더(Builder) 객체이다.

예를 들어

```java
http
    .csrf(csrf -> csrf.disable())
    .formLogin(Customizer.withDefaults())
    .authorizeHttpRequests(auth -> auth
        .anyRequest().authenticated()
    );
```

이 코드는

```text
CSRF 설정

로그인 설정

인가(권한) 설정
```

을 HttpSecurity 내부에 차곡차곡 쌓는 과정이다.

즉,

```text
HttpSecurity
=
Spring Security 설정서
```

라고 생각하면 된다.

---

# 2. build()는 무엇을 하는가?

```java
return http.build();
```

를 호출하면

```text
설정만 가지고 있던 HttpSecurity를

실제로 동작하는 SecurityFilterChain으로 변환한다.
```

---

## 개념적 흐름

```text
설정 작성
      ↓

HttpSecurity
      ↓ build()

SecurityFilterChain
      ↓

실제 요청 처리
```

---

# 3. SecurityFilterChain이란?

SecurityFilterChain은

```text
HTTP 요청이 통과하는 보안 필터들의 목록
```

이다.

요청이 Controller로 바로 가지 않고

먼저 SecurityFilterChain을 통과한다.

---

## 예시

```text
사용자 요청
      ↓

SecurityContextHolderFilter
      ↓

CsrfFilter
      ↓

LogoutFilter
      ↓

UsernamePasswordAuthenticationFilter
      ↓

AuthorizationFilter
      ↓

Controller
```

실제로는 이보다 훨씬 많은 필터가 존재한다.

---

# 4. build() 내부에서 일어나는 일

개념적으로는 아래와 비슷하다.

```java
SecurityFilterChain chain =
    new DefaultSecurityFilterChain(
        requestMatcher,
        filters
    );
```

즉,

```text
HttpSecurity
      ↓

필터 목록 생성
      ↓

DefaultSecurityFilterChain 생성
      ↓

반환
```

과정이 수행된다.

---

# 5. Spring Boot 시작 시 동작

보통 아래와 같이 작성한다.

```java
@Bean
public SecurityFilterChain securityFilterChain(
        HttpSecurity http) throws Exception {

    http
        .authorizeHttpRequests(auth -> auth
            .anyRequest().authenticated()
        )
        .formLogin(Customizer.withDefaults());

    return http.build();
}
```

Spring Boot가 시작되면

```text
@Bean 발견
      ↓

SecurityFilterChain 등록
      ↓

Tomcat 앞단에 연결
      ↓

모든 요청이 SecurityFilterChain 통과
```

하게 된다.

---

# 6. 이전에 배운 인증 흐름과 연결

우리가 본 인증 흐름은

```text
AuthenticationFilter
      ↓

AuthenticationManager
      ↓

AuthenticationProvider
      ↓

SecurityContextHolder
```

였다.

여기서

```text
AuthenticationFilter
```

는 사실 SecurityFilterChain 안에 들어있는 필터 중 하나이다.

---

## 실제 구조

```text
SecurityFilterChain

├─ SecurityContextHolderFilter
├─ CsrfFilter
├─ LogoutFilter
├─ UsernamePasswordAuthenticationFilter
├─ AuthorizationFilter
└─ ...
```

---

# 7. UsernamePasswordAuthenticationFilter의 역할

로그인 요청이 들어오면

```text
아이디 추출
      ↓

비밀번호 추출
      ↓

UsernamePasswordAuthenticationToken 생성
      ↓

AuthenticationManager 호출
```

을 수행한다.

즉,

우리가 공부한 로그인 인증 과정은

```text
UsernamePasswordAuthenticationFilter
```

에서 시작된다.

---

# 8. JPA와 비교

JPA에서

```java
EntityManagerFactoryBuilder
      ↓ build()

EntityManagerFactory
```

관계와 비슷하다.

---

Spring Security에서는

```java
HttpSecurity
      ↓ build()

SecurityFilterChain
```

이다.

---

# 최종 정리

```text
HttpSecurity
=
보안 설정을 작성하는 Builder

SecurityFilterChain
=
실제로 요청을 처리하는 보안 필터 체인

http.build()
=
설정을 바탕으로 SecurityFilterChain 생성

UsernamePasswordAuthenticationFilter
=
SecurityFilterChain 내부의 로그인 인증 필터
```
