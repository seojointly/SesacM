# @ControllerAdvice vs @RestControllerAdvice 차이점 및 활용 가이드

스프링 프레임워크(Spring Framework)에서 전역 예외 처리를 담당하는 두 어노테이션, `@ControllerAdvice`와 `@RestControllerAdvice`의 핵심 차이점과 상황별 선택 기준을 정리한 가이드입니다.

---

## 1. 핵심 차이점: 반환하는 '데이터의 형태'

결론부터 말씀드리면, 두 어노테이션의 관계는 `@Controller`와 `@RestController`의 관계와 완전히 같습니다. `@RestControllerAdvice`는 `@ControllerAdvice`에 **`@ResponseBody`가 추가된 형태**입니다.

### 🔍 `@RestControllerAdvice` 내부 구조
```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Documented
@ControllerAdvice // <--- `@ControllerAdvice`를 포함하고 있음
@ResponseBody     // <--- 모든 메서드에 `@ResponseBody`가 자동으로 적용됨
public @interface RestControllerAdvice { ... }
```

### 📊 비교 테이블

| 기능 | `@ControllerAdvice` | `@RestControllerAdvice` |
| :--- | :--- | :--- |
| **주요 목적** | 전통적인 **Spring MVC** 애플리케이션 예외 처리 | **RESTful 웹 서비스(API)** 애플리케이션 예외 처리 |
| **기본 반환 타입** | **View(화면)** 이름 또는 `ModelAndView` | **객체 데이터** (JSON / XML 등) |
| **`@ResponseBody`** | 기본적으로 없음 (필요 시 메서드에 개별 추가) | **기본 포함** (모든 메서드에 자동으로 적용) |

---

## 2. 언제, 어떨 때 어떤 것을 사용해야 할까?

프로젝트의 **아키텍처와 최종 반환 타입**에 따라 선택하시면 됩니다.

### 💡 `@RestControllerAdvice`를 사용하는 경우 (추천)
최근 대부분의 모던 웹 개발(백엔드와 프론트엔드가 분리된 구조)에서 표준으로 사용됩니다.
* **대상:** 리액트(React), 뷰(Vue.js), 앱(iOS/Android)과 통신하는 API 서버
* **특징:** 예외가 발생했을 때 HTML 화면이 아니라, **에러 코드와 에러 메시지가 담긴 JSON 데이터**를 반환해야 할 때 사용합니다.

#### 🛠️ 예시 코드
```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(UserNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleUserNotFound(UserNotFoundException ex) {
        ErrorResponse error = new ErrorResponse("USER_NOT_FOUND", ex.getMessage());
        return new ResponseEntity<>(error, HttpStatus.NOT_FOUND); // JSON 데이터로 자동 변환되어 응답
    }
}
```

### 💡 `@ControllerAdvice`를 사용하는 경우
서버 사이드 렌더링(SSR)을 사용하여 서버에서 직접 화면을 완성하여 클라이언트에게 전달할 때 사용됩니다.
* **대상:** Thymeleaf, JSP, Mustache 등을 사용하는 전통적인 Spring MVC 웹 애플리케이션
* **특징:** 예외가 발생했을 때 특정 **에러 페이지(예: `error/500.html`)로 화면을 이동(Redirect/Forward)**시켜야 할 때 사용합니다.

#### 🛠️ 예시 코드
```java
@ControllerAdvice
public class WebExceptionHandler {

    @ExceptionHandler(Exception.class)
    public String handleException(Exception ex, Model model) {
        model.addAttribute("errorMessage", ex.getMessage());
        return "error/500"; // templates/error/500.html 뷰 화면을 렌더링
    }
}
```

---

## 3. 요약 및 실무 팁

* **API 서버를 빌드한다** ➡️ `@RestControllerAdvice` 사용
* **화면(HTML)을 반환하는 서버를 빌드한다** ➡️ `@ControllerAdvice` 사용

### 📌 실무 꿀팁 (혼합형 구조)
만약 하나의 프로젝트 내에서 화면도 반환하고(Thymeleaf), 일부 Ajax 통신용 API도 같이 제공하는 혼합형 구조라면 어떻게 해야 할까요?

1. **`@ControllerAdvice`를 기본으로 사용:** 기본적으로 화면 예외 처리를 담당하게 하되, API 예외를 처리하는 메서드 위에만 `@ResponseBody`를 개별적으로 붙여줍니다.
2. **범위(Scope) 지정 분리:** `@ControllerAdvice(annotations = Controller.class)`와 `@RestControllerAdvice(annotations = RestController.class)`처럼 대상 컨트롤러 어노테이션이나 패키지 단위로 범위를 지정하여 두 개의 Advice 클래스를 명확히 분리하여 관리하는 것이 좋습니다.
