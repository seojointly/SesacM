# 객체 생성 패턴 정리 (JPA 기준)

---

# 왜 `new` 생성자를 지양할까?

자바에서 객체 생성의 기본은 생성자 호출이다.

```java
User user = new User(
    "홍길동",
    "hong@test.com",
    "010-1234-5678",
    "서울시",
    25
);
```

하지만 엔티티(Entity) 생성 시에는 여러 문제가 발생한다.

---

## 1. 가독성이 떨어진다

```java
User user = new User(
    "홍길동",
    "hong@test.com",
    "010-1234-5678",
    "서울시",
    25
);
```

코드를 보는 순간

- 첫 번째 값이 무엇인지
- 두 번째 값이 무엇인지
- 어떤 필드에 들어가는지

즉시 파악하기 어렵다.

---

## 2. 순서 실수를 컴파일러가 잡아주지 못한다

```java
User user = new User(
    "hong@test.com",
    "홍길동",
    "010-1234-5678",
    "서울시",
    25
);
```

name과 email의 순서를 바꿨다.

둘 다 String 타입이므로 컴파일 에러가 발생하지 않는다.

실제 실행 후 데이터가 이상하게 저장되어야 발견 가능하다.

---

## 3. 생성자 오버로딩 지옥

요구사항이 늘어나면 생성자가 계속 증가한다.

```java
public User(String name)

public User(String name, String email)

public User(String name, String email, int age)

public User(
    String name,
    String email,
    int age,
    String phone
)
```

점점 관리가 어려워진다.

---

# Builder 패턴

Builder 패턴은 객체 생성 과정을 읽기 쉽게 만들기 위한 패턴이다.

---

## 기존 생성자 방식

```java
User user = new User(
    "홍길동",
    "hong@test.com",
    25
);
```

---

## Builder 방식

```java
User user = User.builder()
    .name("홍길동")
    .email("hong@test.com")
    .age(25)
    .build();
```

---

## 장점

### 가독성

```java
.name("홍길동")
.email("hong@test.com")
.age(25)
```

어떤 값이 어떤 필드에 들어가는지 바로 알 수 있다.

---

### 순서 무관

```java
User.builder()
    .age(25)
    .email("hong@test.com")
    .name("홍길동")
    .build();
```

순서가 바뀌어도 문제 없다.

---

### 필요한 필드만 선택 가능

```java
User.builder()
    .name("홍길동")
    .build();
```

---

# Lombok @Builder

Lombok이 Builder 코드를 자동 생성해준다.

```java
@Builder
public class User {

    private String name;
    private String email;
    private int age;
}
```

사용

```java
User user = User.builder()
    .name("홍길동")
    .email("hong@test.com")
    .age(25)
    .build();
```

---

# JPA에서 Builder 사용하는 이유

JPA 엔티티는 필드가 많아질 가능성이 높다.

```java
@Entity
public class User {

    private String name;
    private String email;
    private String phone;
    private String address;
    private int age;
}
```

Builder를 사용하면 생성 코드의 의도가 명확해진다.

```java
User user = User.builder()
    .name("홍길동")
    .email("hong@test.com")
    .phone("010")
    .build();
```

---

# JPA 엔티티는 기본 생성자가 필요하다

JPA는 조회 시 내부적으로 객체를 생성한다.

예시

```java
User user = new User();
```

비슷한 방식으로 객체를 생성한 뒤 값을 주입한다.

따라서 기본 생성자가 반드시 필요하다.

---

## 권장 방식

```java
@NoArgsConstructor(access = AccessLevel.PROTECTED)
```

생성되는 코드

```java
protected User() {
}
```

---

# 실무에서 많이 사용하는 엔티티 형태

```java
@Entity
@Getter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
public class User {

    private String name;
    private String email;

    @Builder
    public User(
        String name,
        String email
    ) {
        this.name = name;
        this.email = email;
    }
}
```

생성

```java
User user = User.builder()
    .name("홍길동")
    .email("hong@test.com")
    .build();
```

# 정적 팩토리 메서드 (Static Factory Method)

생성자를 직접 노출하지 않고

객체 생성용 메서드를 제공하는 방식이다.

---

## 일반 생성자

```java
User user = new User(
    "홍길동",
    "hong@test.com"
);
```

---

## 정적 팩토리 메서드

```java
public static User createUser(
    String name,
    String email
) {
    User user = new User();
    user.name = name;
    user.email = email;
    return user;
}
```

사용

```java
User user = User.createUser(
    "홍길동",
    "hong@test.com"
);
```

---

# 정적 팩토리 메서드의 장점

## 1. 이름을 가질 수 있다

```java
User.createUser(...)
```

```java
User.createPendingUser(...)
```

```java
User.createAdminUser(...)
```

객체 생성 의도를 명확하게 표현할 수 있다.

---

## 2. 생성 로직을 숨길 수 있다

```java
public static User createUser(
    String name,
    String email
) {
    User user = new User();

    user.name = name;
    user.email = email;
    user.createdAt = LocalDateTime.now();

    return user;
}
```

사용자는 내부 구현을 몰라도 된다.

---

# Builder + 정적 팩토리 조합

실무에서 매우 자주 사용하는 방식

```java
public static User createUser(
    String name,
    String email
) {
    return User.builder()
        .name(name)
        .email(email)
        .build();
}
```

# 비즈니스 메서드

JPA에서는 Setter 남발을 지양한다.

---

## 안 좋은 예

```java
user.setStatus("CANCEL");
user.setUpdatedAt(LocalDateTime.now());
```

왜 변경되는지 알 수 없다.

---

## 좋은 예

```java
public void cancelMembership() {
    this.status = "CANCEL";
    this.updatedAt = LocalDateTime.now();
}
```

사용

```java
user.cancelMembership();
```

행위가 명확하다.

---

# 팩토리 패턴 (Factory Pattern)

객체 생성을 별도 클래스로 분리하는 방식

---

```java
public class UserFactory {

    public static User createAdminUser(
        String email
    ) {
        return User.builder()
            .email(email)
            .role(Role.ADMIN)
            .build();
    }
}
```

사용

```java
User admin =
    UserFactory.createAdminUser(
        "admin@test.com"
    );
```

---

# 프로토타입 패턴 (Prototype Pattern)

기존 객체를 복사해서 새로운 객체를 만드는 방식

---

## 복사 생성자

```java
public Product(Product source) {

    this.name = source.name;
    this.price = source.price;
    this.category = source.category;
}
```

---

## 사용

```java
Product copy =
    new Product(original);
```

---

## 복사 메서드

```java
public Product copyWithNewPrice(
    int newPrice
) {
    Product copy =
        new Product(this);

    copy.price = newPrice;

    return copy;
}
```

사용

```java
Product saleProduct =
    product.copyWithNewPrice(1000);
```

# JPA 실무 권장 방식

## 생성자

```java
@NoArgsConstructor(access = AccessLevel.PROTECTED)
```

JPA용 기본 생성자 제공

---

## 객체 생성

```java
@Builder
```

또는

```java
public static User createUser(...)
```

사용

---

## 값 변경

Setter 사용 최소화

```java
changeEmail()
cancelMembership()
completeOrder()
```

같은 비즈니스 메서드 사용

---

# 한눈에 보는 비교

| 방식 | 장점 | 단점 |
|--------|--------|--------|
| 생성자(new) | 단순함 | 가독성 낮음, 순서 실수 가능 |
| Builder | 가독성 좋음, 순서 무관 | 코드 약간 길어짐 |
| 정적 팩토리 메서드 | 이름으로 의도 표현 가능 | 메서드 수 증가 |
| Factory Pattern | 생성 책임 분리 | 클래스 추가 필요 |
| Prototype Pattern | 기존 객체 복사 가능 | 깊은 복사 주의 |

---

# JPA 실무 결론

```java
@Entity
@Getter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
public class User {

    private String name;
    private String email;

    @Builder
    private User(
        String name,
        String email
    ) {
        this.name = name;
        this.email = email;
    }

    public static User createUser(
        String name,
        String email
    ) {
        return User.builder()
            .name(name)
            .email(email)
            .build();
    }

    public void changeEmail(
        String email
    ) {
        this.email = email;
    }
}
```

실무에서는 보통

- 기본 생성자 → JPA용(PROTECTED)
- 객체 생성 → Builder 또는 정적 팩토리 메서드
- 상태 변경 → 비즈니스 메서드
- Setter 남발 금지

형태를 가장 많이 사용한다.1
