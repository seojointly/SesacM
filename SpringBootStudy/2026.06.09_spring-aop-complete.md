# Spring AOP 완전 정리

> AOP(Aspect-Oriented Programming): 핵심 비즈니스 로직과 공통 기능(로깅, 트랜잭션, 보안 등)을 분리해 모듈화하는 프로그래밍 패러다임

---

## 핵심 개념 구조

```
Aspect
├── Pointcut  →  JoinPoint 중 Advice를 적용할 지점 선택
└── Advice    →  선택된 Pointcut에서 실행될 부가 로직 (위빙할 코드 + 시점)
                   ├── @Before
                   ├── @After
                   ├── @AfterReturning
                   ├── @AfterThrowing
                   └── @Around
```

---

## 1. Aspect

**횡단 관심사(Cross-Cutting Concern)를 하나의 모듈로 묶은 단위**

- 여러 클래스에 반복되는 공통 기능(로깅, 트랜잭션, 보안 등)을 분리한 클래스
- Spring에서는 `@Aspect` + `@Component`로 선언
- Pointcut 정의와 Advice 메서드의 집합

```java
@Aspect
@Component
public class LoggingAspect {
    // Pointcut + Advice 메서드들이 여기 들어감
}
```

---

## 2. JoinPoint

**Advice가 끼어들 수 있는 모든 후보 시점**

- JoinPoint는 Aspect 클래스에 선언하는 게 아님
- **비즈니스 로직이 있는 일반 클래스(Service 등)의 메서드들이 자동으로 JoinPoint 후보가 됨**
- Spring AOP에서는 메서드 호출 시점만 지원 (AspectJ는 필드 접근, 생성자 등도 지원)

```
📁 프로젝트 구조

UserService.java          ← JoinPoint 후보들이 여기 존재
  └── saveUser()          ← JoinPoint (Pointcut에 의해 선택됨)
  └── getUserById()       ← JoinPoint (선택 안됨)
  └── deleteUser()        ← JoinPoint (Pointcut에 의해 선택됨)

LoggingAspect.java        ← Aspect (Pointcut + Advice 정의)
  └── @Pointcut(...)      ← "saveUser, deleteUser 골라!"
  └── @Before             ← 선택된 것들 앞에서 실행
```

```
UserService.java          LoggingAspect.java (Aspect)
─────────────────         ──────────────────────────────
saveUser()     ◀──────── @Pointcut  (이 둘을 선택)
getUserById()             @Before   (선택된 곳에서 실행)
deleteUser()   ◀──────── @Around   (선택된 곳에서 실행)
findAll()
```

> JoinPoint는 "내가 여기야!" 하고 선언하는 게 아니라, 메서드가 존재하는 순간 자동으로 후보가 된다. Pointcut이 그 중에서 필터링하는 역할이다.

Advice 메서드의 파라미터로 `JoinPoint` 객체를 받아 실행 중인 메서드 정보를 꺼낼 수 있다.

```java
@Before("execution(* com.example.service.*.*(..))")
public void logBefore(JoinPoint joinPoint) {
    String methodName = joinPoint.getSignature().getName();   // 메서드 이름
    Object[] args     = joinPoint.getArgs();                  // 파라미터 값들
    String className  = joinPoint.getTarget()
                                 .getClass()
                                 .getSimpleName();            // 대상 클래스 이름
}
```

## 3. Pointcut

**JoinPoint 중에서 실제 Advice를 적용할 지점을 선별하는 표현식**

### 기본 사용

```java
@Before("execution(* com.example.service.UserService.*(..))")
public void logBefore() { ... }
```

### 재사용을 위한 분리 선언

```java
@Aspect
@Component
public class LoggingAspect {

    @Pointcut("execution(* com.example.service.*.*(..))")
    public void serviceLayer() {}

    @Before("serviceLayer()")
    public void logBefore() { ... }

    @After("serviceLayer()")
    public void logAfter() { ... }
}
```

### execution 표현식 읽는 법

```
execution(* com.example.service.*.*(..))
           │ └────────────────┘ │ └──┘
           │      패키지 경로    │  파라미터 무관
           │                    └─ 모든 메서드명
           └─ 리턴타입 무관
```

| 표현식 예시 | 의미 |
|---|---|
| `execution(* com.example.service.*.*(..))` | service 패키지의 모든 클래스, 모든 메서드 |
| `execution(* com.example.service.UserService.*(..))` | UserService의 모든 메서드 |
| `execution(* save*(..))` | 이름이 save로 시작하는 모든 메서드 |
| `execution(public * *(..))` | public 메서드 전체 |

## 4. Advice

**위빙할 코드(내용) + 위빙 시점(언제)을 함께 정의하는 것**

```java
@Before("serviceLayer()")        // ← 언제 끼워넣을지 (위빙 시점)
public void logBefore(JoinPoint jp) {
    System.out.println("시작");   // ← 끼워넣을 코드 (위빙 내용)
}
```

### Advice 종류

| 종류 | 동작 시점 | 반환 타입 | 매개변수 타입 |
|---|---|---|---|
| `@Before` | 메서드 실행 이전 | `void` | `JoinPoint` |
| `@After` | 메서드 실행 이후 | `void` | `JoinPoint` |
| `@Around` | 메서드 실행 이전/이후 | `Object` | `ProceedingJoinPoint` |
| `@AfterReturning` | 예외 없는 메서드 실행 이후 | `void` | `JoinPoint` |
| `@AfterThrowing` | 예외 발생한 메서드 실행 이후 | `void` | `JoinPoint` |

### 각 Advice 실행 흐름

Spring AOP는 **프록시 패턴**으로 동작한다. 진짜 객체를 직접 호출하는 게 아니라, Spring이 만든 프록시 객체가 중간에서 가로챈다.

```
[ 호출자 ]  →  [ 프록시 객체 ]  →  [ 진짜 UserService ]
                  ↑
             여기서 Advice 실행
```

**@Before**
```
프록시 진입 → @Before 실행 → 진짜 메서드 실행 → 결과 반환
```
- Before가 예외를 던지면 진짜 메서드는 아예 실행 안 됨
- 파라미터를 읽을 수만 있고 변경 불가

**@After**
```
프록시 진입 → 진짜 메서드 실행 → @After 실행 (무조건)
```
- Java의 `finally` 블록과 동일한 개념
- 정상/예외 무관하게 항상 실행, 반환값 접근 불가

**@AfterReturning**
```
프록시 진입 → 진짜 메서드 실행 → 정상 반환 시에만 @AfterReturning 실행
                                → 예외 발생 시 실행 안 됨
```
- 반환값을 읽을 수는 있지만 변경 불가

**@AfterThrowing**
```
프록시 진입 → 진짜 메서드 실행 → 예외 발생 시에만 @AfterThrowing 실행
                                → 예외는 그대로 호출자에게 전파됨
```
- 예외를 삼키는 게 아님, 처리 후 예외는 계속 올라감

**@Around**
```
프록시 진입 → Around 앞부분 → pjp.proceed() → 진짜 메서드 → Around 뒷부분 → 결과 반환
```
- `pjp.proceed()`를 호출해야 진짜 메서드가 실행됨
- 호출 안 하면 메서드 실행 자체를 막을 수 있음 (캐싱, 차단 로직 등)
- 반환값 조작 가능

```java
@Around("serviceLayer()")
public Object around(ProceedingJoinPoint pjp) throws Throwable {
    System.out.println("전");           // @Before 역할

    Object result = pjp.proceed();      // 진짜 메서드 호출

    System.out.println("후: " + result); // @AfterReturning 역할

    return result;                      // 반환값 조작 가능
}
```

### 여러 Advice가 동시에 걸릴 때 실행 순서

정상 실행 시:
```
@Before → @Around 앞 → 메서드 → @Around 뒤 → @AfterReturning → @After
```

예외 발생 시:
```
@Before → @Around 앞 → 메서드(예외) → @AfterThrowing → @After
```

## 5. Weaving (위빙)

**Advice(부가 로직)를 JoinPoint(대상 메서드)에 끼워 넣는 행위 자체**

Advice의 Before/After 실행, 프록시 동작 등이 전부 위빙의 결과물이고, **언제 끼워 넣냐**에 따라 3가지 방식으로 나뉜다.

```
[ .java 소스 ]
      │
      │ 1. 컴파일 타임 위빙 (AspectJ 컴파일러)
      ▼
[ .class 파일 ] ← 이미 Advice 코드가 박혀있음
      │
      │ 2. 클래스 로딩 타임 위빙 (Java Agent)
      ▼
[ JVM 메모리 ] ← 로딩 순간에 바이트코드 조작
      │
      │ 3. 런타임 위빙 (Spring 기본 방식)
      ▼
[ 프록시 객체 ] ← 실행 중에 프록시가 중간에서 가로챔
```

| 방식 | 도구 | 원본 클래스 변경 | Spring 기본 |
|---|---|---|---|
| 컴파일 타임 | AspectJ 컴파일러 | ✅ .class에 직접 삽입 | ❌ |
| 클래스 로딩 타임 | AspectJ + Java Agent | ❌ 원본 유지 | ❌ |
| 런타임 | Spring AOP (프록시) | ❌ 원본 유지 | ✅ |

> **Spring이 런타임 위빙을 기본으로 쓰는 이유**: 컴파일/로딩 타임 위빙은 AspectJ라는 별도 도구와 복잡한 설정이 필요하지만, 런타임 방식은 프록시 객체 하나만 끼워넣으면 되기 때문이다.

> **런타임 위빙의 한계**: `private` 메서드나 같은 클래스 내부 호출엔 AOP가 걸리지 않는다. 프록시를 거치지 않고 직접 호출되기 때문이다. 이 경우엔 AspectJ(컴파일 타임 위빙)를 사용해야 한다.

## 전체 코드 예시

```java
@Aspect
@Component
public class LoggingAspect {

    // Pointcut 정의
    @Pointcut("execution(* com.example.service.*.*(..))")
    public void serviceLayer() {}

    // 메서드 실행 전 로깅
    @Before("serviceLayer()")
    public void logBefore(JoinPoint jp) {
        System.out.println("[LOG] 시작 - " + jp.getSignature().getName());
    }

    // 예외 발생 시 로깅
    @AfterThrowing(pointcut = "serviceLayer()", throwing = "ex")
    public void logException(JoinPoint jp, Exception ex) {
        System.out.println("[ERROR] " + jp.getSignature().getName() + " - " + ex.getMessage());
    }

    // 실행 시간 측정
    @Around("serviceLayer()")
    public Object measureTime(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.currentTimeMillis();
        Object result = pjp.proceed();
        long end = System.currentTimeMillis();
        System.out.println("[TIME] " + pjp.getSignature().getName() + " - " + (end - start) + "ms");
        return result;
    }
}
```

## 한 줄 비유

| 개념 | 비유 | 역할 |
|---|---|---|
| **Aspect** | CCTV 시스템 전체 | 횡단 관심사 모듈 |
| **Advice** | CCTV가 찍는 동작 + 설치 시점 | 위빙할 코드 + 시점 |
| **JoinPoint** | CCTV 설치 가능한 모든 위치 | 개입 가능한 모든 시점 (자동 후보) |
| **Pointcut** | 실제 카메라를 설치할 위치 선별 규칙 | 적용할 JoinPoint 필터 |
| **Weaving** | 카메라를 실제로 설치하는 행위 | Advice를 JoinPoint에 끼워넣는 것 |
