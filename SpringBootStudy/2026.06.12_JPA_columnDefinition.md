# Java JPA columnDefinition 기능 및 활용 가이드

`@Column` 어노테이션의 `columnDefinition` 속성은 JPA가 **데이터베이스 스키마를 자동으로 생성(DDL Auto)할 때, 특정 컬럼의 데이터 타입과 제약조건을 SQL 문법으로 직접 지정하는 기능**입니다.

JPA가 자바 타입을 기반으로 추론하여 자동으로 만들어주는 SQL 대신, **개발자가 원하는 특정 DB 전용 SQL 문법을 그대로 컬럼 정의에 주입**하고 싶을 때 사용합니다.

---

## 1. 주요 활용 시점

JPA는 기본적으로 자바 객체의 필드 타입(예: `String`, `int`)을 분석해 적절한 DB 타입(`VARCHAR`, `INT`)을 매칭합니다. 하지만 다음과 같은 특수한 요구사항이 있을 때 `columnDefinition`이 필수적으로 사용됩니다.

* **DB 레벨의 기본값(DEFAULT)을 설정해야 할 때**
* **특정 DB 전용 특수 타입(예: MySQL의 `TEXT`, `LONGTEXT`, `JSON`, `ENUM` 등)을 명시해야 할 때**
* **복합적인 제약조건(예: `CHECK` 제약조건)을 데이터베이스 스키마에 강제하고 싶을 때**

---

## 2. 구체적인 코드 예시

### ① 기본값 (DEFAULT) 설정
데이터가 누락된 채로 `INSERT` 될 때, DB 차원에서 기본값을 채워주도록 설정합니다.

```java
@Entity
public class User {

    @Id @GeneratedValue
    private Long id;

    // 문자열 기본값 설정
    @Column(columnDefinition = "varchar(255) default 'USER'")
    private String role;

    // 숫자형 기본값 설정
    @Column(columnDefinition = "integer default 0")
    private int viewCount;

    // 시간/날짜 기본값 설정 (현재 시간 자동 입력)
    @Column(columnDefinition = "timestamp default CURRENT_TIMESTAMP")
    private LocalDateTime createdAt;
}
```

### ② 대용량 텍스트 및 특수 타입 지정
자바의 `String`은 기본적으로 `VARCHAR(255)`로 매핑되는 경우가 많습니다. 게시글 본문처럼 대용량 데이터가 필요하거나 특수 포맷을 다룰 때 유용합니다.

```java
@Entity
public class Post {

    @Id @GeneratedValue
    private Long id;

    // 대용량 텍스트 타입 지정 (MySQL의 TEXT)
    @Column(columnDefinition = "TEXT")
    private String content;

    // 데이터베이스 전용 JSON 타입 활용 예시
    @Column(columnDefinition = "json")
    private String metadata;
}
```

### ③ DB 레벨의 제약조건 (Check) 추가
어플리케이션 검증 외에 데이터베이스 자체에서 값의 유효 범위를 엄격하게 제한하고 싶을 때 사용합니다.

```java
@Entity
public class Product {

    @Id @GeneratedValue
    private Long id;

    // 나이가 19세 이상인지 DB 레벨에서 검증하도록 설정
    @Column(columnDefinition = "integer check (age >= 19)")
    private int age;
}
```

## 3. 주의해야 할 단점 및 한계

`columnDefinition`은 세밀한 제어가 가능하다는 장점이 있지만, 프로젝트의 유지보수성을 낮출 수 있는 치명적인 단점이 존재하므로 주의해야 합니다.

1. **데이터베이스 종속성 (DB Dialect 파괴)**
   * `columnDefinition` 내부 문자열은 **실제 가동 중인 특정 DB의 문법**을 따릅니다. 예를 들어 MySQL 전용 문법을 적어두면, 향후 Oracle이나 PostgreSQL로 DB를 전환할 때 DDL 에러가 발생합니다. (데이터베이스 독립성이라는 JPA 본연의 장점이 희석됨)
2. **컴파일 시점 오타 방지 불가능**
   * 자바 문자열(`""`) 내부에 SQL을 직접 적기 때문에 컴파일러가 문법 오류를 잡아내지 못합니다. 애플리케이션을 구동하여 DDL 스크립트가 실행되는 런타임 시점에 비로소 에러를 발견하게 됩니다.
3. **DDL Auto 생성 시에만 동작**
   * `spring.jpa.href.ddl-auto` 옵션이 `create`나 `create-drop` 등 테이블을 새로 생성할 때만 적용됩니다. 기존에 운영 중인 상용 DB 테이블 구조를 `columnDefinition` 변경만으로 자동 마이그레이션 해주지 않습니다.

---

## 💡 대안 및 권장사항

* 단순 글자 수 제한은 `columnDefinition = "varchar(100)"` 대신 **`@Column(length = 100)`**을 사용하는 것이 DB 독립성을 유지하는 데 좋습니다.
* 대용량 데이터는 **`@Lob`** 어노테이션을 조합하여 사용하는 구조를 우선적으로 검토하세요.
* `columnDefinition`은 표준 속성들(`length`, `nullable`, `@Lob` 등)만으로 표현할 수 없는 **`DEFAULT` 값 지정**이나 **특수 타입 매핑**이 정말로 필요할 때 제한적으로 사용하는 것이 가장 이상적입니다.
