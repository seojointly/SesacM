# JPA 엔티티에서 @ToString 사용을 권장하지 않는 이유

## 핵심 요약

JPA 엔티티에 Lombok의 `@ToString`을 사용하면 연관관계 필드까지 자동으로 출력하려고 하기 때문에, 양방향 연관관계가 존재하는 경우 순환참조(무한루프)가 발생할 수 있다.

따라서 JPA 엔티티에서는 `@ToString` 사용을 지양하거나, 연관관계 필드를 제외하고 직접 `toString()`을 작성하는 것이 일반적이다.

---

## 순환참조란?

예를 들어 아래와 같은 양방향 연관관계가 있다고 가정한다.

### Member

```java
@Entity
public class Member {

    @Id
    private Long id;

    private String name;

    @ManyToOne
    private Team team;
}
````

### Team

```java
@Entity
public class Team {

    @Id
    private Long id;

    private String name;

    @OneToMany(mappedBy = "team")
    private List<Member> members = new ArrayList<>();
}
```

객체 관계는 다음과 같다.

```text
Member
  ↕
Team
```

---

## @ToString 사용 시 발생하는 문제

```java
@Getter
@Setter
@ToString
@Entity
public class Member {
    ...
}
```

Lombok은 내부적으로 다음과 비슷한 코드를 생성한다.

```java
@Override
public String toString() {
    return "Member(id=" + id +
           ", name=" + name +
           ", team=" + team + ")";
}
```

여기서 `team`을 출력하기 위해 `team.toString()`이 호출된다.

그런데 Team의 `toString()` 안에는 `members`가 포함되어 있다.

```java
@Override
public String toString() {
    return "Team(name=" + name +
           ", members=" + members + ")";
}
```

`members`를 출력하는 과정에서 다시 `Member.toString()`이 호출된다.

결과적으로 다음과 같은 호출이 반복된다.

```text
Member.toString()
    ↓
Team.toString()
    ↓
Member.toString()
    ↓
Team.toString()
    ↓
...
```

무한 반복이 발생하며 결국

```text
java.lang.StackOverflowError
```

가 발생할 수 있다.

---

## 실무에서 사용하는 표현

다음과 같은 표현이 가장 일반적이다.

```java
// JPA 엔티티 설계 시 @ToString 사용 권장 X
// 양방향 연관관계에 의한 순환참조 발생 가능
```

또는

```java
// 연관관계 상호참조로 인한 무한 루프 발생 가능
```

---

## 해결 방법

### 방법 1. 연관관계 필드 제외

```java
@ToString(exclude = "team")
@Entity
public class Member {
}
```

```java
@ToString(exclude = "members")
@Entity
public class Team {
}
```

---

### 방법 2. 직접 toString 작성 (실무 선호)

```java
@Override
public String toString() {
    return "Product{" +
            "id=" + id +
            ", productCode='" + productCode + '\'' +
            ", name='" + name + '\'' +
            ", price=" + price +
            '}';
}
```

연관관계 필드는 출력하지 않는다.

---

## IntelliJ Generate toString 사용 시 체크 기준

### 포함(O)

```java
private Long id;
private String name;
private int price;
private LocalDateTime createdAt;
```

### 제외(X)

```java
@ManyToOne
private Category category;

@OneToMany
private List<Order> orders;

@OneToOne
private User user;

@ManyToMany
private List<Tag> tags;
```

---

## 실무 규칙

| 필드 종류       | toString 포함 여부 |
| ----------- | -------------- |
| id          | O              |
| name        | O              |
| price       | O              |
| createdAt   | O              |
| @ManyToOne  | X              |
| @OneToMany  | X              |
| @OneToOne   | X              |
| @ManyToMany | X              |

결론:

> JPA 엔티티에서는 연관관계 필드를 toString()에 포함하지 않고, 일반 컬럼만 출력하는 것이 안전한 방법이다.
