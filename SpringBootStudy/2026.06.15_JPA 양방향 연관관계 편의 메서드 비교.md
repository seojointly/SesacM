# JPA 양방향 연관관계 편의 메서드 비교

JPA에서 양방향 연관관계를 맺을 때, 객체 그래프를 일관성 있게 유지하기 위해 **연관관계 편의 메서드(Convenience Method)** 를 작성한다.

대표적으로 다음 두 가지 구현 방식이 존재한다.

---

# 1. 구현 방식 비교

## 방식 A : `== null` (강사님 버전)

```java
public void addOrderItem(OrderItem item) {
    this.orderItems.add(item);

    // 자식의 부모가 아직 없는 경우에만 설정
    if (item.getOrder() == null) {
        item.setOrder(this);
    }
}
```

### 특징

- 부모가 지정되지 않은 새로운 자식 객체만 연결
- 이미 부모가 있는 객체는 건드리지 않음

### 장점

- 코드가 단순함
- 학습용 예제에서 가장 많이 사용
- 무한 재귀 방지 목적에 적합

### 단점

- 이미 다른 부모가 설정된 객체를 재할당할 수 없음

---

## 방식 B : `!= this` (방어적 구현)

```java
public void addOrderItem(OrderItem item) {
    this.orderItems.add(item);

    // 현재 부모가 내가 아니면 무조건 변경
    if (item.getOrder() != this) {
        item.setOrder(this);
    }
}
```

### 특징

- 부모가 없든
- 이미 다른 부모가 있든
- 현재 부모가 내가 아니면 무조건 나로 변경

### 장점

- 객체 재사용 가능
- 비즈니스 변경에 유연
- 실무에서 더 방어적인 코드

### 단점

- 의도를 모르면 조금 덜 직관적일 수 있음

---

# 2. 핵심 차이

| 비교 항목                 | `== null` 방식 | `!= this` 방식        |
| ------------------------- | -------------- | --------------------- |
| 성능                      | 동일           | 동일                  |
| 목적                      | 최초 연결      | 현재 부모를 나로 강제 |
| 이미 부모가 존재하는 경우 | 변경 안 함     | 변경함                |
| 객체 재사용               | 어려움         | 가능                  |
| 학습용 예제               | 적합           | 가능                  |
| 실무 확장성               | 보통           | 높음                  |

---

# 3. 예시로 이해하기

## 현재 상태

```text
OrderA
 └─ MacBook

OrderB
 └─ (비어 있음)
```

---

## 방식 A (`== null`)

```java
orderB.addOrderItem(macBook);
```

실행 과정

```java
if (macBook.getOrder() == null)
```

결과

```java
false
```

따라서

```java
macBook.setOrder(orderB);
```

가 실행되지 않는다.

최종 상태

```text
OrderA
 └─ MacBook

OrderB
 └─ MacBook (리스트에만 추가됨)
```

객체 그래프가 꼬일 수 있다.

---

## 방식 B (`!= this`)

```java
orderB.addOrderItem(macBook);
```

실행 과정

```java
if (macBook.getOrder() != orderB)
```

결과

```java
true
```

따라서

```java
macBook.setOrder(orderB);
```

실행

최종 상태

```text
MacBook.order = OrderB
```

주인이 정상적으로 변경된다.

---

# 4. 성능 차이는 있을까?

## 결론

성능 차이는 사실상 0%

이유:

```java
item.getOrder() == null
```

또는

```java
item.getOrder() != this
```

둘 다

- 메모리 주소 비교 1회
- CPU 수준 연산

에 불과하다.

---

## DB 쿼리도 동일

두 방식 모두 최종적으로

```java
item.setOrder(this);
```

를 호출한다.

따라서 생성되는 SQL도 동일하다.

예시

```sql
insert into order_item ...
```

또는

```sql
update order_item
set order_id = ?
```

쿼리 개수와 성능 차이는 없다.

---

# 5. 실무형 구현

실무에서는 기존 부모와의 관계까지 정리해 주는 형태를 많이 사용한다.

```java
public void addOrderItem(OrderItem item) {

    // 1. 내 컬렉션에 추가
    this.orderItems.add(item);

    // 2. 기존 부모가 있다면 제거
    if (item.getOrder() != null
            && item.getOrder() != this) {

        item.getOrder()
            .getOrderItems()
            .remove(item);
    }

    // 3. 새로운 부모 지정
    if (item.getOrder() != this) {
        item.setOrder(this);
    }
}
```

---

# 6. 실무 관점

실제 프로젝트에서는 다음 상황이 발생할 수 있다.

- 주문 상품 재배정
- 장바구니 이동
- 환불 후 재주문
- 관리자 기능으로 데이터 수정
- 부모 엔티티 변경

이 경우

```java
!= this
```

방식이 더 안전하다.

---

# 7. 면접 포인트

면접 질문:

> 연관관계 편의 메서드에서 `== null` 과 `!= this` 의 차이는 무엇인가요?

답변 예시:

> `== null` 방식은 최초 연관관계 설정만 허용하는 단순한 구현입니다.
>
> 반면 `!= this` 방식은 현재 부모가 누구든 상관없이 연관관계를 현재 객체로 동기화하는 방어적 구현입니다.
>
> 성능 차이는 없으며, 실무에서는 객체 재사용 및 관계 변경 가능성을 고려해 `!= this` 방식이 더 유연합니다.

---

# 최종 결론

- 학습 및 예제 코드
  - `== null` 사용 가능

- 실무 코드
  - `!= this` 권장

- 성능 차이
  - 없음

- 가장 안전한 방식
  - 기존 부모 컬렉션까지 정리하는 실무형 편의 메서드 사용
